# 翻译加速上线操作单（2026-10-21）

> 目标：把短句翻译从 **1.9~4.2 秒** 降到 **0.2~0.4 秒**。
> 结论先行：代码与迁移都已就绪，**剩下的两步在管理后台，不在代码里**。

---

## 一、为什么慢（实测数据，不是推断）

真机 `SEND_PERF` 日志，66 条真实消息：

```
total     2022ms
├─ translate  1906ms   ← 94%，全在上游模型
└─ 客户端      116ms   ← 已无可优化空间
```

管理后台 `/translate/engines` 返回的通道阵容（改前）：

| 通道 | 模型 | 类型 | 实测 P50 | 实测 P95 |
|---|---|---|---|---|
| `gpt` | `gpt-5.6-luna` | 对话式（推理模型） | **4179ms** | 5577ms |
| `deepseek` | `deepseek-flash` | 对话式（已关思考） | **1381ms** | 1779ms |

**两条都是 LLM**：`prompt → 推理 → 逐 token 生成`。
你对比的 Google / DeepL 是 seq2seq 专用翻译模型，**不生成**，所以 100~300ms。

> 注：日志里曾出现 1926ms，那是命中缓存或短句。
> 全新文本的 GPT 实际是 **4.2 秒**，比体感更慢。

## 二、改了什么

### 1. 混合路由（新增）

`server/services/translation-router.js`

```
短句（≤120 字符、单行、无占位符/链接/表格）→ 快速通道（qwen-mt-flash）
其余                                       → LLM（保语气、术语、格式）
```

按真机长度分布，**63% 的消息会命中快速通道**。

### 2. 恢复 qwen 通道（迁移 047）

`migrations/047_restore_qwen_fast_channel.js`

- 只恢复 `advanced` / `pro` 两档，**`basic` 不动**（该档单位成本最高，不往里加成本）
- `qwen` 行本来就在库里（039 是软下架），只清 `retired_at`
- **不写 `wired = true`** —— 凭据在后台加密落库，迁移拿不到。
  硬写 true 就是谎报「通道已接通」，用户一选就 502

### 3. 透明度（守住既有约束）

`resolveEngineId` 头部有一条硬约束：**「不得静默切换供应商」**。所以：

- 路由只发生在**套餐内已接通**的通道之间，绝不跳过权益校验
- 响应带 `routed: {from, to, reason}`
- 译文角标显示「· 快速通道」，悬停看完整来源
- 成本台账记**实际供应商**（否则月度对账会凭空多/少一块）
- 缓存键区分通道（避免「换了路由却拿到旧译文」）
- 总开关 `PIX_HYBRID_ROUTING` **默认关闭**，关闭时行为与改前逐字节一致

## 三、上线步骤

### 第 1 步：跑迁移

```bash
# 在部署机上，仓库目录内
npm run migrate            # 或你们平时用的迁移入口
```

**这一步只改权益表，不碰账务**（`char_balance` / `char_used` / `translate_logs` 一律不动）。

验证：

```sql
SELECT id, enabled, wired, retired_at FROM engines WHERE id = 'qwen';
-- 期望：enabled=t, wired=f, retired_at=NULL
```

`wired=f` 是**正常的**，第 2 步填完 Key 才变真。

### 第 2 步：后台填 API Key（关键）

管理后台 → 翻译通道 → **通义千问翻译** → 填 API Key → 保存。

从哪里拿 Key：

1. 登录 [阿里云百炼控制台](https://bailian.console.aliyun.com/)
2. 开通「模型服务」→ 找到 **qwen-mt-flash**
3. 创建 API-KEY（格式 `sk-xxxx`）

保存后 `wired` 会由适配器自动置真。验证：

```sql
SELECT id, wired FROM engines WHERE id = 'qwen';
-- 期望：wired=t
```

> **这一步不做，后面全部无效。** 未接通的通道会被路由层自动跳过，
> 行为与改动前完全一致（不会报错，但也不会有加速）。

### 第 3 步：确认账号权益在 v4

```sql
SELECT u.username, p.code, u.package_catalog_version
FROM users u JOIN packages p ON p.id = u.package_id
WHERE u.username = 'ahao';
```

**期望 `package_catalog_version = 4`。**

如果还是 `3`（钉在旧版本上），说明迁移第 3 节没把它释放过来 ——
这是**有意的**：已售权益不因新通道上线被悄悄扩展，也不被悄悄削掉。
需要走一次套餐变更 / 续费，或在后台手动把该字段置 NULL（= 跟随在售版本）。

### 第 4 步：打开混合路由

在 `/etc/hello-pix/hello-pix.env` 里加：

```bash
PIX_HYBRID_ROUTING=1
PIX_FAST_ENGINES=qwen
```

重启服务：

```bash
systemctl restart hello-pix    # 或你们的重启方式
```

`PIX_FAST_ENGINES` 支持逗号分隔、按优先级，例如：

```bash
PIX_FAST_ENGINES=qwen,google   # qwen 优先，没有就退 google
```

## 五、回滚

**最快**：去掉环境变量里的 `PIX_HYBRID_ROUTING=1`，重启。
路由立刻停止，行为回到改前（短句也走 LLM）。**不用回滚数据库。**

**完全回滚**：

```bash
npm run migrate:down    # 回退 047
```

会把 qwen 重新下架、权益退回 v3。
**注意**：这不改已发生的账，但用户会失去 qwen 选项。

## 六、已知限制

1. **`basic` 档没有 qwen** —— 该档会继续走 LLM（1.4~4.2 秒）。
   等快速通道的实测收益出来，再决定是否放开：
   加一条迁移把 `['basic','qwen']` 加进集合即可。

2. **qwen-mt 单条输入上限 8192 tokens** —— 超了厂商直接报错。
   适配层已在本地拦截并给中文提示（不会把厂商错误码丢给用户）。

3. **120 字符是权衡值，不是物理极限**。
   实测中位 51 字符、48% 在 50 以内，120 覆盖日常一句到两三句。
   超过 120 通常是整段复制，此时 LLM 的语气/格式保真收益开始大于等待成本。
   要调就改 `translation-router.js` 的 `FAST_MAX_CHARS`，并同步更新那条边界用例。

4. **多行 / 含占位符 / 含链接 / 表格一律走 LLM** —— 这些交给专用翻译 API 会翻车
   （多行被揉成一段、`{name}` 被翻译掉、链接被搞坏）。
   规则表在 `SLOW_MARKERS`，每条都有对应用例。
