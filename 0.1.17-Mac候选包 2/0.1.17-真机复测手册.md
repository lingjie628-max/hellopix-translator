## 复测 1（P0-2）点「译」→ 中文必须紧跟被点的那条消息下面

**前提**：一个**群聊**（翻译模式 = 手动），群里至少有一条英文消息。

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | 打开群聊，找到那条消息上的「译」按钮 | 按钮显示在该**消息气泡**内 |
| 2 | 点「译」 | 按钮变「翻译中…」，随后**变绿/变「已翻译」** |
| 3 | 看译文位置 | **中文必须出现在你点的那条消息的气泡内、紧跟原文下方** |
| 4 | 特别检查 | 译文**不得**出现在整个聊天区域的底部、也不得出现在列表末尾 |

**FAIL 判据（任一即 FAIL）**：译文出现在聊天底部 / 会话根 / 消息列表末尾 / 输入框附近 / 全局浮层；
或消息显示「已翻译」但看不到译文；或按钮点下去没有任何变化。

### 这一轮做了什么（为什么这次不会再漂到底部）

老代码 `hostOf()` 是**向上兜底**的，而且两处入参不同：

```
扫描挂按钮：hostOf(span.selectable-text) → 落到内层 .text-content / .copyable-text
渲染译文　：hostOf(row[data-id])        → 行自己不在 .copyable-text 里 → 一路 closest
                                          → 命中 [data-testid="msg-container"]（消息列表容器）→ 画到聊天底部
最后一档 `|| node` 更是彻底没有边界。
```

现在：

- `hostOf()` **只从消息行向下推导**（`rowOf` → `bubbleFromSpan`），结果**一定是被点那条 `[data-id]` 行的后代**，
  结构上不可能是 `#main` / 列表根 / footer / overlay。**找不到就返回 null。**
- `#main`、`msg-list`、conversation root、footer、last child、全局 overlay **全部列入禁止名单**，
  命中即拒绝绘制。
- 找不到精确原消息 → `TRANSLATION_RENDER_TARGET_MISSING`，**这条消息显示翻译失败**，绝不换地方画。
- 绘制之后还有一道**硬校验**：译文节点必须真的挂在原消息行内；
  校验不过就丢弃并记 `TRANSLATION_RENDER_UNVERIFIED`，绝不显示「已翻译」。

## 复测 2（P0-1）制造一次翻译失败 → 点「重试翻译」→ 必须真正重试并成功发送

**制造失败**（任选其一，挑最容易复现的）：

- 翻译通道未接通 / 余额不足（后台临时改一下即可）；
- 或在点击发送的瞬间断开网络，让 `/translate/run` 失败。

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | 输入一句中文，按回车 | 被拦下（**对方什么都收不到**），弹失败提示 |
| 2 | 看提示 | 提示里应有 **「错误码：XXXX」** 一行（真实原因，不再是一句笼统的「翻译失败」） |
| 3 | 恢复条件（接通通道 / 联网） | — |
| 4 | 点「重试翻译」 | 立刻显示「正在重试…」 |
| 5 | 等结果 | **真正重翻并发送成功**；提示自动收起；**不得**再出现「重试失败」 |

**FAIL 判据（任一即 FAIL）**：点「重试翻译」→ 又回到「重试失败」；原文被退回输入框且没有发出译文；
按钮点了没反应；提示里看不到错误码。

### 这一轮做了什么（为什么这次能闭环）

- 重试**不再复用**上一轮的 `sendActionId` / 残留 `phase`：点击瞬间换新 `sendActionId`、把 `phase` 归零、
  清 `sendBusy`/`pendingSend`。老实现失败时直接 `return`，`phase` 永远停在 `translating`，
  重试带着残留状态进状态机 → 被判成陈旧动作 → 「重试失败」。
- `deliverSend` 失败分支现在会把 `phase` **归位**（不再留残留）。
- 发送链改用**带错误码**的翻译调用（`translateTextDetailed`），失败原因一路带到界面与日志，
  **禁止**再用统一的「状态异常/重试失败」掩盖。
- 全链路留痕：`RETRY_TRANSLATE_CLICK` → `TRANSLATE_STARTED` → 响应/错误 → `FINAL_TEXT_VALIDATED`
  → `PROGRAMMATIC_SEND_BEGIN` → `PROGRAMMATIC_SEND_DONE` → `RETRY_TRANSLATE_RESULT(code)`。

它会重点抽出这几行，正是判定两个 P0 的直接证据：

| 事件 | 说明 |
|---|---|
| `RETRY_TRANSLATE_CLICK` | 点下「重试翻译」（带新的 sendActionId） |
| `RETRY_TRANSLATE_RESULT` | 重试收口 + **真实错误码** |
| `MANUAL_TRANSLATE_CLICK` | 点击时记录的真实 `data-id` / `byPath` / `rowHasDataId` |
| `TARGET_RELOCATED` | 重定位命中的 `rowId` / 宿主标签类名 / `textMatches` |
| `TRANSLATION_RENDER_VERIFIED` | ✅ 译文确实挂在原消息行内 |
| `TRANSLATION_RENDER_UNVERIFIED` | ❌ 绘制后复核没过 → 已丢弃 |
| `TRANSLATION_RENDER_TARGET_MISSING` | ❌ 找不到精确原消息 → 不显示（也不会放底部） |

