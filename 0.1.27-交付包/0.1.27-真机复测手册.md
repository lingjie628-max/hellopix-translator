## 一、本轮改了什么

### 第 1 层（网页）—— `desktop/guest-inject.js`

译文框 `.pix-trans` 的选中权用 `!important` + 两种前缀写死：

```css
user-select: text !important;
-webkit-user-select: text !important;
```

另加 `selectstart` / `copy` 事件守卫：宿主若在气泡层捕获并 `preventDefault`，
我们在 **document 捕获阶段**先把事件掐断（宿主收不到），并对译文框整段选中兜底。
**只对 `.pix-trans` 生效**，普通消息区域照旧传给宿主。

### 第 2 层（Electron 主进程）—— `desktop/main.js`

新增三样，互为兜底：

1. **`installEditSupport(view)`**：给每个 `WebContentsView` 挂
   `before-input-event`（接住 Cmd/Ctrl+C/V/X/A → 调 `webContents.copy()/paste()/cut()/selectAll()`）
   和 `context-menu`（右键「复制 / 剪切 / 粘贴 / 全选」）。**这条路不依赖菜单**，最稳。
2. **`installApplicationMenu()`**：macOS 装一份含编辑角色
   （undo/redo/cut/copy/paste/selectAll）的应用菜单 —— Electron 在 macOS 上靠它把
   `Cmd+C/V/A` 转发到聚焦的 webContents。Windows/Linux 用 `setMenu(null)`，快捷键走第 1 条。
3. `createWebView()` 里对每个 view 调用 `installEditSupport(view)`。

### 已跑过的自动验证（交付前实测）

- 全量测试：**1122 项 / 1108 通过 / 0 失败**（14 跳过）。
- 源码装载校验：**19 / 19**。
- **真 Electron 机制验收 `npm run verify:copy`：8 / 8** —— 真实 Chromium 里复刻宿主禁选，
  证明译文能选中、`Cmd+C` 进剪辑板、全选/粘贴/右键复制均生效、非译文区域不受影响。
- 两架构 `app.asar` 逐字节相同（`sha256 be0e9aec…`）。

## 三、验收 A — ★本轮唯一目标★ 译文可选中、可复制

> 在**任意**已适配的聊天窗口里（WhatsApp / Telegram 优先，各测一遍最好），
> 让页面上出现一条**已翻译**的消息（中文译文显示在原文下方）。

### A1. 鼠标拖动选中译文

1. 用鼠标从译文开头拖到结尾。
2. **期望**：译文出现**蓝色高亮**（能选中）。
3. **0.1.26 失败态**：拖过去没有任何高亮，选区是空的。

### A2. `Cmd+C` 复制译文

1. 选中译文（A1）。
2. 按 `Cmd+C`。
3. 打开「备忘录 / 文本编辑」，`Cmd+V`。
4. **期望**：粘贴出来的**就是那句译文**。
5. **0.1.26 失败态**：粘贴不出来，剪辑板是旧的或空的。

### A3. `Cmd+A` 全选

1. 焦点放在聊天消息区，按 `Cmd+A`。
2. **期望**：选区非空、包含译文内容。
3. **0.1.26 失败态**：毫无反应。

### A4. 右键菜单复制

1. **右键点击**译文区域。
2. **期望**：弹出菜单，含「复制」（可编辑时还有剪切/粘贴、以及「全选」）；点「复制」能复制。
3. **0.1.26 失败态**：右键毫无反应（`WebContentsView` 默认不弹系统菜单）。

### A5. 输入框粘贴

1. 点聊天输入框，按 `Cmd+V`（先把一段文字放进剪辑板）。
2. **期望**：文字被粘进输入框 —— 注意**不要**因此触发发送翻译的错误链路，粘完清掉即可。

### A6. ★不越界★ 原文照旧

1. 选中**原始消息正文**（不是译文），`Cmd+C` → 粘贴。
2. **期望**：原文照旧能复制（我们的修复只针对译文，不该影响宿主自身的选择行为）。
