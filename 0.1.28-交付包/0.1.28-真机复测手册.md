# 0.1.28 Mac 候选 — 真机复测手册（图文消息发送不翻译）

> 本轮修的是用户报的**功能缺陷**：「图文一起发送的时候，不翻译」。
>
> | # | 真机现象 | 根因（两层，缺一不可） |
> |---|---|---|
> | **A** | 附加图片后输入中文，按回车 / 点发送按钮 → **中文原文直接发出去**，消息发送成功 | 第 1 层：`composerEl()` 只按选择器顺序取「第一个可见输入框」，附件预览面板里有**多个** `contenteditable`，拿到的不是用户正在打字的 caption 框 → 读到的正文是空 |
> | **B** | 客户端日志里**一条发送拦截记录都没有**（不是翻译失败，是根本没拦） | 第 2 层：`eventInComposer(event, composerEl())` 要求"事件发生在焦点框里"。**焦点没跟着切到 caption 框**（用户多半是"先打字、再附加图片"）→ 焦点框 ≠ 事件框 → 判定失败 → 静默放行 |
>
> ### 期望行为（本轮目标）
>
> | 操作 | 期望 |
> |---|---|
> | 先打字 → 再附加图片 → 打字（caption）→ 回车 | **被拦下并翻译**，发出的只有译文，且只发一条 |
> | 附加图片 → 直接在 caption 打字 → 回车 | 同上 |
> | 附加图片 → 点发送按钮 | 同上 |
> | 正常（无附件）发消息 | 行为**完全不变** |
> | 发英文/已是目标语言 | 照旧直发，不误翻 |
> | 媒体标题框（文件名等）里的内容 | **不被当成正文翻译** |
> | 接收方向：带文字的图片 | 正文正常翻译（不会被时间戳/回执污染） |
>
> **本机是 Apple 芯片 → 用 arm64 包。**
> **本轮不动套餐 / 代理 / 群组 / 子账号 / 复制粘贴逻辑。**

## 一、本轮改了什么

### 第 1 层（输入框定位）—— `desktop/guest-inject.js`

新增 `isEditableEl(el)`：判「能不能输入」**以 `contenteditable` 属性为准**，
`isContentEditable` 仅作补充（它是宿主派生属性，在嵌套 contenteditable / shadow DOM
等场景可能给 `undefined`，一旦假阴性就会退回错误分支）。

`composerEl()` 改为**优先返回 `document.activeElement`**（用户正在打字的框），
选择器顺序仅作兜底。

### 第 2 层（发送拦截入口）—— `desktop/guest-inject.js`

新增 `boxFromEvent(event)` 与 `sendTargetBox(event)`：**事件优先、焦点兜底**。

只要事件本身发生在某个可编辑框里，就以**它**为准 —— 与焦点无关。
`onKeyDown` / `onBeforeInput` / `onClick` 三处入口全部改用它。

### 取证日志（下次同类问题不再两眼一抹黑）

| 日志行 | 含义 |
| --- | --- |
| `SEND_NOT_INTERCEPTED` | **本该拦下却没拦**。带原因 / 事件类型 / 命中的框 / 事件目标 / 当前可见输入框候选 |
| `COMPOSER_FOCUS_MISMATCH` | 事件框与焦点框不一致（正是本缺陷现场） |
| `SEND_CAPTURED` → `NATIVE_SEND_BLOCKED` → `TRANSLATE_STARTED` → `INPUT_REPLACED` → `PROGRAMMATIC_SEND_BEGIN` | 正常拦截链路（**缺任何一环**都说明这条没走通） |

### 已跑过的自动验证（交付前实测）

- 全量测试：**1132 项 / 1118 通过 / 0 失败**（14 跳过）。
- **真 Electron 机制验收 `npm run verify:send-intercept`：15 / 15** ——
  真实 Chromium 里复刻"附件预览面板（两个 contenteditable）"，证明：
  - 焦点在 caption → 命中 caption；
  - **焦点不在 caption（真机现场）→ 旧路径 `oldPathWouldIntercept: false`（漏判/静默放行）
    vs 新路径 `newPathIntercepts: true`**；
  - 事件在标题框 → 解析出的就是标题框自己（不会被误当正文）。
- 两架构 `app.asar` 逐字节相同（`sha256 85ba295c…`）。
- 两个 DMG 均已挂载复核：版本 `0.1.28`，包内含本次全部修复。

## 三、复测步骤（按顺序做，每步记结果）

### 准备

- 开一个 WhatsApp 会话（**最好是自己给自己发消息**，或发给可信任的人），
  这样出问题不会打扰对方。
- 客户端翻译方向设为「中文 → 英文」（或你的常用方向），发送翻译**开启**。

### T1｜先打字，再附加图片，再按回车（★本轮主场景）

1. 在聊天输入框打一段中文（**先不要发**）。
2. 点回形针 / 图片按钮，选一张图。
3. 在弹出的预览里，往说明文字框（caption）里补一句中文。
4. **按回车**。

**期望**：消息**没有立刻发出**，而是先被拦下 → 翻译 → 发出的是**英文译文**，且**只有一条**。
**若出现中文原文直接发出** → 记录时间，立刻做第四节的日志采集。

### T2｜附加图片后直接在 caption 打字 → 回车

同上，但第 1 步不打字，直接附加图片后在 caption 打中文。
**期望**：同样被拦下并翻译。

### T3｜点发送按钮（而不是回车）

重复 T1/T2，但最后**点预览面板上的发送按钮**。
**期望**：同样被拦下并翻译（不是"点按钮就绕过"）。

### T4｜正常消息（无附件）—— 防回归

不附加任何东西，打中文 → 回车。
**期望**：和以前**一模一样**（拦下 → 翻译 → 只发一条译文）。

### T5｜不需要翻译的消息 —— 防误拦

发一条纯英文（或已经是目标语言）的消息。
**期望**：照旧直发，**不会被翻译、不会被拦**。

### T6｜媒体标题框里的内容 —— 防误翻

附加图片，若预览里有"标题/文件名"之类的输入框，往里面打点文字。
**期望**：**不会被当成正文翻译**。

### T7｜接收方向：带文字的图片

让对方（或自己用另一账号）发一张**带文字说明的图片**。
**期望**：图片下方的正文能正常翻译（译文不会混进时间戳、已读回执等杂项）。

### T8｜复制粘贴 —— 防回归（0.1.27 的修复）

在聊天窗口里拖动选中一句中文**译文** → `Cmd+C` → 粘到备忘录。
**期望**：能选中、能复制出译文。（此为本包继承的 0.1.27 修复，不该回退。）

## 四、如果又出问题：日志采集

沿用 0.1.27 的采集脚本：

```bash
cd 0.1.27-交付包
./rc027-collect.sh
```

把生成的压缩包回传。**重点看这几行**（它们能把现场还原到"哪一层断的"）：

| 现象 | 日志特征 | 说明 |
| --- | --- | --- |
| 原文直接出网，**什么都没记** | 完全没有 `SEND_*` | 拦截入口没走到 —— 需要新的现场信息 |
| 原文直接出网，有记录 | `SEND_NOT_INTERCEPTED {...}` | **本来就是这条日志的用途**：看 `reason` / `box` / `target` / `candidates` |
| 记录了 `COMPOSER_FOCUS_MISMATCH` | 焦点框 ≠ 事件框 | 命中本缺陷现场（但新路径应当仍然拦住） |
| 拦下了但没发出去 | 有 `SEND_CAPTURED` 无 `INPUT_REPLACED` | 翻译或写回环节的问题 |
| 发出了但内容不对 | 有 `PROGRAMMATIC_SEND_BEGIN` | 看它前面那行 `发送翻译 · 最终正文=` |

> 日志里**不含消息正文**（只记长度与 hash），可以直接回传。
