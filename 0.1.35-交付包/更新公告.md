## 版本一：标准版（推荐，适合群公告 / 官网）

### 🎉 Hello Pix 0.1.35 已发布：修复「节点检测失败」

最近一段时间，有用户反馈：**同一个代理节点，在别的工具里能用，在 Hello Pix 里却检测失败。**

这个问题的原因已经查清，是我们自己引入的缺陷，已在本版修复。

**1️⃣ 修好了「好节点被判成坏节点」**

从 0.1.29 起，我们在检测节点时**额外加了一道检查**，
这道检查只要没通过，就直接判定节点不可用，**不再继续验证节点是否真的能用**。

结果就是：一些本来能正常使用的节点被提前判死。

现在这道检查**只保留一种作用**——当节点完全没有任何响应时提前中止
（避免界面长时间卡在「正在检测」）。

其余情况下，一律以「**能不能真的经这个节点打开网页**」为准。
也就是说：**判定方式和最早能用时的版本保持一致**。

**2️⃣ 修正了容易误导的错误提示**

之前节点检测失败时，会提示：

- 「节点拒绝了连接（可能是流量用尽、套餐到期或 IP 白名单未加）」

这个说法**不准确**。它会让用户以为是自己的套餐到期了，从而去换节点、找服务商，
但真正的故障其实在我们这边。

现在这类提示已按网络协议的标准含义改正。**如果你之前因为这个提示换过节点，
建议把原来的节点填回来重新检测一次。**

**3️⃣ 节点检测已恢复可用**

修复后，同一个节点在本软件中检测成功，可正常显示 IP 与国家/地区信息（例如 Singapore）。

## 附：这次问题的完整来龙去脉（内部留档，不必对外）

| 版本 | 节点检测的判定方式 | 结果 |
|---|---|---|
| ≤ 0.1.28 | Chromium 经代理**真的打开网页**，拿到 IP 才算通过 | 正常 |
| 0.1.29 | **新增纯 Node 预检作为强制门**，CONNECT 拿不到 `0x00` 就直接失败 | **回归开始** |
| 0.1.30 ~ 0.1.31 | 未改判定逻辑 | 仍失败 |
| 0.1.32 | 改了 `0x08` 的提示文案（改成「流量用尽/套餐到期」） | 仍失败，且**解释错误** |
| 0.1.33 | 改为多目标并发试探、改文案 | 仍失败 |
| **0.1.35** | 预检**只拦 TIMEOUT**，其余以真实网页加载为准 | **修复** |

关键点：

- 同一个节点、同一台机器、同一套账号密码，**旧版能过、新版必死** —— 因果链闭合。
- `0x08` 在网络协议（RFC1928）里的标准含义是 `Address type not supported`
  （节点处理不了这次连接请求的地址），**不是**账号欠费。0.1.32 的解释没有依据。
- 0.1.29 当初加这道预检是为了修「检测转圈卡死」，那个 P0 **确实存在**
  （无响应的节点会让 Chromium 卡在握手并弄坏渲染进程）。
  本版保留了对 `TIMEOUT` 的拦截，所以**那个问题不会复发**。
