# Hello Pix 原生计数工单

## 需求口径

Hello Pix 内部直接实现“计数工单 / 新粉 / 重粉”功能，不嵌入、不启动外部计数器软件，也不复用已经下线的 `orders`、`order_details`、`order_fans` 空表。

计数规则：

1. **一个计数工单只属于一个应用**，例如 WhatsApp 工单与 Telegram 工单完全独立。
2. 同一工单可以绑定该应用下的多个接入账号；同一商户的同一个“应用 + 账号”同时只能属于一个进行中的同应用工单。
3. 一条 `conversation` 只贡献一个进粉事件；同一会话发多少消息都不会重复加粉。
4. 同一客户第一次进入计数系统算新粉。
5. 同一客户在同一应用内从另一条会话、另一个账号或另一个商户的计数工单再次出现，算重粉；换一个应用重新算新粉。
6. “今日”按工单自己的 IANA 时区和每日置零时间计算，不跟随后端服务器时区。
7. 计数写入失败不能阻断客户消息接入；同一会话下次上报仍可幂等补记。
8. 计数工单沿用套餐 `clients.counter` 权益；`basic` / `advanced` 默认无权限，`pro` / `solo_monthly` 可用。
9. 客户身份合并后，同一客户会在**每个应用内分别重排**进粉事件：每个应用最早一条为新粉，其余为重粉。
10. 工单产生第一条进粉记录后，业务时区和每日置零时间锁定，避免历史业务日口径漂移。

## 数据模型

迁移：`migrations/054_count_tickets.js`。

- `count_tickets`
  - 归属商户 `user_id`
  - 名称、计数应用、状态、单日目标、总目标
  - 业务时区、每日置零时间
- `count_ticket_accounts`
  - 工单绑定的平台账号
  - `(user_id, platform, account_key)` 的启用态唯一索引，防止一账号同时进入两个进行中工单
- `count_ticket_fans`
  - 进粉事件账本
  - 保存会话、客户、平台、接入账号、事件时间、业务日、新/重粉类型
  - `(ticket_id, conversation_id)` 唯一，保证会话去重

所有内容层表都带 `user_id`，并用 `(ticket_id, user_id)` 复合外键绑定工单归属。

## 后端

- `server/repositories/count-ticket-repository.js`：数据访问、统计 SQL、幂等进粉账本。
- `server/services/count-ticket-service.js`：参数校验、绑定账号、新/重粉判定、商户隔离。
- `server/routes/count-tickets.js`：商户端建单、编辑、绑定账号、明细查询。
- `server/routes/admin/count-tickets.js`：超管只读查看。
- `/customer/ingest` 成功写入会话后旁路调用计数；计数异常只记录日志，不影响主链路。
- 商户接口统一校验 `clients.counter`，无权益返回 `COUNT_PLAN_REQUIRED`。

### 商户接口

```text
GET  /apis/count-tickets
GET  /apis/count-tickets/:id
GET  /apis/count-tickets/:id/fans
POST /apis/count-tickets/save
POST /apis/count-tickets/accounts/save
POST /apis/count-tickets/accounts/remove
GET  /apis/count-tickets/available-accounts
```

### 超管接口

```text
GET /apis/admin/count-tickets
GET /apis/admin/count-tickets/:id
GET /apis/admin/count-tickets/:id/fans
```

超管接口使用 `admin.data.customers` 能力，普通 operator 不可见。

## 前端

- 商户：`#/count/tickets`
- 超管：`#/admin/count-tickets`

商户页支持新建/编辑工单、绑定/停用账号、今日与累计新/重粉卡片、账号拆分统计和粉丝明细筛选。

注意：当前桌面端上报的 `accountKey` 是客户端接入账号 slug，不等同于
WhatsApp/Telegram 的真实聊天号码，因此页面统一称为“接入账号”。

## 回滚

```bash
node scripts/migrate.js down 1
```

这条 down 只删除本次新增的三张计数表，不影响 `customers`、`conversations`、`messages`、充值或翻译账本。
