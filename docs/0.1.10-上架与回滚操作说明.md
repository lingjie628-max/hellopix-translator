## 0.1.10 的内容（相对 0.1.9）

**只修代理这一条 P0，不动其他功能、不重构。** 就是「带账号密码的代理必报
`net::ERR_NO_SUPPORTED_PROXIES`」这个缺陷：

- 根因：账密被拼进 `proxyRules`（`socks5://账号:密码@主机:端口`）。
  Chromium 的规则串**只接受地址**，收到内嵌凭据即拒绝。
- 修法（按线路 / partition 分发凭据，规则串里**永不含凭据**）：
  - **HTTP/HTTPS**：规则只写 `host:port`，Basic 凭据由 `app.on('login')` 回填；
    只响应 `authInfo.isProxy === true`（网站自身的 Basic Auth 一律放行，
    避免把代理账密错误用于站点登录），且只按触发挑战的 webContents 取凭据 ——
    线路 A 的账密不可能被线路 B 用上。
  - **SOCKS5**：Chromium 不为 socks5 触发 login，改用**每线路独立的本地回环中继**
    （`desktop/socks-relay.js`，`127.0.0.1` 随机端口、不复用），
    认证发生在「中继 → 上游」。
- 顺带修好：修改已存在线路的代理**立即生效**、删除代理**恢复直连**（不再静默退回旧代理）；
  节点探测同样支持带认证代理。
- 安全：读远程页面改走隔离世界（新增 `desktop/probe-page.js`），不再用 page-world
  `executeJavaScript`；打包白名单补上 `socks-relay.js` / `probe-page.js`。

**计费规则本轮未改**（V1.0.x：仅开放 DeepSeek 与 GPT，共用同一 `char_balance`，
倍率 1.0x）。该规则在**服务端**生效，与客户端版本无关。

## 上架（已执行，留档）

见 `deploy/register-client-0.1.10.sql`。要点：

```sql
-- 1) 下架旧版（保留文件与记录，留作回滚）
UPDATE client_releases SET enabled = false, updated_at = NOW()
 WHERE release_group IN ('windows','macos') AND version <> '0.1.10' AND enabled = true;

-- 2) 上架 0.1.10（upsert，重复执行不会出错）
INSERT INTO client_releases (release_group, title, os, arch, app, version, url, enabled, note)
VALUES ('windows','Windows 安装版','Windows','x64','','0.1.10',
        'https://pixfanyi.com/downloads/HelloPix-Setup-0.1.10.exe', true, '...')
ON CONFLICT (release_group, os, arch, app, version) DO UPDATE
  SET url = EXCLUDED.url, enabled = true, updated_at = NOW();
```

**为什么必须同时下架旧版**：更新接口按「该系统的已上架记录」挑一条返回。
两条同为 `arch = x64`、得分相同时，选中哪条取决于排序 —— 会出现
**有的用户收到新版、有的收不到**的随机现象。

上架后自测（要登录）：

```bash
curl -s "https://pixfanyi.com/apis/client/update?os=win32&arch=x64"
```

## 回滚

```sql
UPDATE client_releases SET enabled = false, updated_at = NOW() WHERE version = '0.1.10';
UPDATE client_releases SET enabled = true,  updated_at = NOW() WHERE version = '0.1.9';
```

回滚只是让**更新提示**回到 0.1.9，**不会**把已经装成 0.1.10 的用户变回去。
真要让用户退回，得再发一个版本号更大的包（客户端只认更大的版本号）。

> ⚠️ **本次回滚的代价比平时大**：0.1.9 正是那个「带账号密码的代理不可用」的版本
> （见上文根因）。回滚到 0.1.9 等于把这条 P0 重新放回线上。
> 若回滚原因是 0.1.10 引入了新问题，应优先热修复并升到 **0.1.11**，而不是回退到 0.1.9。
