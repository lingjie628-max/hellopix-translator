# 工单计数融合进 Hello Pix：需求理解

## 需求概述

把现有《WhatsApp 进粉计数》的核心能力嵌入 Hello Pix 翻译软件：

- 进粉计数
- 全局新粉/重粉判定
- 自动生成进粉工单
- 工单跟进与状态统计

不再使用独立的计数软件，不新增邀请码、激活码或 `CENTRAL_TOKEN`。
用户只登录现有 Hello Pix 账号，计数模块复用该账号、设备绑定和多开 WhatsApp 会话。

本需求中的“工单”指**客户进粉后自动生成的跟进工单**，不是现有商户向平台客服提交的
“客服工单”。两套业务必须分表、分权限、分页面名称，避免状态和统计混在一起。

## 功能需求

### P0 - 必须实现

- [ ] **复用 Hello Pix 登录**
  - 计数模块不单独注册、不单独登录、不要求邀请码。
  - 使用现有主账号/子账号、设备绑定和 HTTPS 客户端会话。
- [ ] **按 WhatsApp 实例开启计数**
  - 复用“添加应用”里已经存在但尚未接线的“开启计数器”开关。
  - 每个 WhatsApp 多开实例是独立计数账号，可设置备注名。
- [ ] **实时采集所有私聊入站消息**
  - 不要求用户停留在当前聊天页。
  - 后台标签页、隐藏标签页收到私聊消息时也要立即进入计数链路。
  - 群聊、广播、状态、我方发出的消息、纯 reaction/system 消息默认不计粉。
- [ ] **身份归一化**
  - 优先使用 WhatsApp 手机号。
  - 只有 LID 时先用 LID 暂存；后续拿到手机号时自动合并为同一客户。
  - 同一客户不能因为 LID、号码、不同设备而被重复算成多个新粉。
- [ ] **全局新粉/重粉**
  - 全平台第一次见：新粉。
  - 同一 Hello Pix 主账号下的其他子账号或设备历史见过，但当前计数账号第一次见：
    全局重粉。
  - 当前计数账号已经见过：重复联系，不增加进粉数，也不新增工单。
- [ ] **实时更新**
  - 服务端判定完成后立即返回本次类型、当前计数和工单号。
  - 当前设备界面立即刷新；多设备数据以服务端为准。
- [ ] **自动生成进粉工单**
  - 每条新粉/重粉流水立即且只生成一张工单。
  - 新粉普通优先级，重粉高优先级。
  - 重复推送、页面重扫、断线重放不能重复建单。
- [ ] **计数台**
  - 今日新粉、今日重粉、累计新粉、唯一客户。
  - 实时流水、按账号筛选、日期筛选、CSV 导出。
- [ ] **重粉库**
  - 展示客户被同一主账号下几个子账号/设备见过。
  - 不向一个商户暴露其他独立商户的数据。
- [ ] **进粉工单**
  - 工单列表、详情、备注、负责人、状态流转、超时提示。
  - 状态至少包含：待处理、处理中、等待客户、已解决、已关闭。
- [ ] **账号删除与清零**
  - 删除/归档最后一个计数账号后，当前工作区的进粉数显示为 0。
  - 历史流水和工单永久保留在数据中心，可由主账号或超管查询。
- [ ] **失败不丢数据**
  - 服务端不可达时，事件进入本机待上传队列。
  - 网络恢复后自动补传；服务端按幂等键去重。
- [ ] **权限隔离**
  - 主账号可看本账号下全部计数账号和工单。
  - 子账号只能看自己有权限的设备和工单。
  - 超管可看全平台数据中心。

### P1 - 重要功能

- [ ] 离线期间显示“待数据中心判重”，恢复后自动转成新粉/重粉。
- [ ] 工单 SLA、负责人分配、内部备注和时间线。
- [ ] 多端实时同步未读数和关键 KPI。
- [ ] 旧计数软件 SQLite/中央库数据导入工具。
- [ ] 按商户、设备、账号、日期导出对账报表。

### P2 - 可选功能

- [ ] 群消息引流统计。
- [ ] 客户合并的人工审核与回滚。
- [ ] 多语言界面继续复用现有语言包。

## 非功能需求

- **实时性**：新消息被网页观察器捕获后 2 秒内完成服务端判定和界面更新；网络异常时显示待同步。
- **正确性**：同一消息、同一账号、同一客户必须幂等；计数以服务端事实表为唯一权威。
- **并发安全**：两个账号同时首次看到同一客户时，只能有一个产生“全局新粉”，另一个必须是“重粉”。
- **隐私**：计数上报只发送身份、时间和消息类型，不为了计数重复上报聊天正文。
- **可观测性**：每次忽略、计数、判重、建单和失败都要有结构化日志。
- **兼容性**：Windows x64、macOS Intel、macOS Apple Silicon 行为一致。
- **可回滚**：迁移可 down，桌面计数开关默认关闭，关闭后不影响聊天和翻译。

## 边界与约束

- 不包含：独立计数 EXE、独立登录、邀请码、中央看板令牌。
- 不包含：Baileys 第二次连接同一个 WhatsApp 账号。
- 不包含：跨独立商户共享客户线索；这里的“全局”默认指同一 Hello Pix 主账号下的
  全部子账号和设备。
- 技术限制：WhatsApp Web 的内部事件模块不是公开 API，升级后可能变化，必须能力发现并失败关闭。
- 技术限制：桌面软件完全退出时不产生新计数；关闭窗口但后台运行时继续计数。
- 外部依赖：现有 Hello Pix API、PostgreSQL、Redis、桌面多开 WebContentsView。

## 验收标准

### 复用登录、无邀请码

- Given 用户已使用 Hello Pix 主账号或子账号登录并完成设备绑定，
  When 用户开启某个 WhatsApp 实例的计数器，
  Then 计数模块直接开始工作，不出现邀请码、激活码或数据中心令牌输入框。

### 实时采集

- Given 计数实例处于后台标签页且用户正在另一个应用聊天，
  When 该 WhatsApp 账号收到一条私聊消息，
  Then 2 秒内产生一条待判定事件，不需要用户点开该聊天。

### 全局新粉/重粉

- Given 客户 A 的手机号从未进入平台，
  When 账号 1 第一次收到 A 的消息，
  Then 计数为“新粉”并立即生成普通优先级工单。

- Given 客户 A 已经在同一主账号下的其他设备或账号出现，
  When 账号 2 第一次收到 A 的消息，
  Then 计数为“全局重粉”并立即生成高优先级工单。

- Given 账号 2 已经给 A 计过粉，
  When A 再发多条消息或页面重扫，
  Then 状态为“重复联系”，计数不增加且不新建工单。

### 身份合并

- Given 客户先以 LID 被记录，
  When 后续事件同时拿到其手机号和 LID，
  Then 两个身份合并为同一客户，历史流水和工单跟随合并，不增加假新粉。

### 并发判重

- Given 两个账号在不同设备几乎同时首次收到客户 A，
  When 两条事件并发到达服务端，
  Then 只允许一条成为新粉，另一条为重粉，流水总数仍为 2。

### 删除账号

- Given 本工作区只有一个计数账号且已有进粉历史，
  When 用户删除该账号，
  Then 当前计数台所有“现役账号”汇总归零；
  Then 历史流水、重粉记录和工单仍可在数据中心查询。

### 失败恢复

- Given 数据中心暂时不可达，
  When 收到新私聊消息，
  Then 本机先写入待上传队列且不把未知事件擅自标成新粉；
  When 网络恢复，
  Then 自动补传并由服务端给出最终新粉/重粉结果。
