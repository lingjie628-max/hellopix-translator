### 问题清单

#### 🔴 严重问题

#### 🟡 建议修改

**问题 1：还缺真实 PostgreSQL 并发验收**

- 位置：`migrations/053_counter_integration.js`、`server/services/counter-service.js`
- 问题：本机没有 PostgreSQL/Redis 测试实例，SQL 执行、迁移 `up/down` 和
  advisory lock 的真库并发行为未实际跑过。逻辑路径已用 fake repository
  覆盖，全量测试中的 16 个数据库集成项被跳过。
- 风险：若生产库与测试库版本、约束或事务行为不同，可能出现迁移失败或并发
  重粉判定异常。
- 建议：上线前在隔离 PostgreSQL 上执行 053 迁移，并跑以下三条：
  - 两账号同时首见同一客户 → 1 新粉 + 1 重粉；
  - 同一消息并发重放 → 只生成 1 条流水和 1 张工单；
  - LID 后补手机号 → 合并同一客户，不新增假粉。

**问题 2：还缺已登录 WhatsApp 的真机消息事件验收**

- 位置：`desktop/src/translate/whatsapp-counter-observer.js`
- 问题：模块名、导出结构和 `isNewMsg` 已从当前 WhatsApp bundle 核实，但本次
  没有用已登录账号实际接收一条客户消息。
- 风险：WhatsApp 后续改内部集合事件签名时，观察器可能进入 `unavailable`
  状态，导致真实进粉不计数。
- 建议：上线前用两个独立 WhatsApp 实例验证：
  - 后台私聊新消息能触发 `[pix-counter-observer] ready` 和进粉中心实时刷新；
  - 群聊、本人消息、旧历史回补不计数；
  - 断网后恢复，本地 outbox 能补传且不重复。

**问题 3：安装包仍为未签名 / 未公证**

- 位置：本次 `/tmp` 构建产物
- 问题：macOS 是 ad-hoc 签名、无公证；Windows 无 Authenticode 签名。
- 风险：用户首次打开会被系统安全提示拦截，且无法证明安装包发布者身份。
- 建议：沿用用户明确授权时可发布未签名版本；正式品牌发布应补 Apple
  Developer ID + 公证、Windows 代码签名证书。

### 亮点

- 消息先落本地 outbox，再请求服务端；同一 `sourceMessageId` 重放由服务端
  `(counter_account_id, source_message_id)` 唯一约束兜底。
- 进粉事实和自动工单在同一 PostgreSQL 事务内创建，避免“有计数没工单”。
- 身份指纹使用 HMAC；平台消息 ID、会话 ID 只落 SHA-256，不把 WhatsApp
  原始标识直接写进事实表。
- 关闭计数实例会排队归档；归档账号从当前汇总排除，但历史流水和工单保留。
- 原生进粉中心复用现有 Hello Pix 登录/设备绑定，不引入邀请码和旧 EXE。
