# macOS 未公证版安装引导 · 客服手册

> 适用客户端：**0.1.6 及以上**（含 0.1.11）。这些版本的 `.app` 已做 **ad-hoc 签名**，
> 用户**能自己放行**。
> 背景与签名机制见 `docs/macOS安装包签名与已损坏问题.md`；本文是**客服执行手册**。

---

## 一、先判断用户属于哪种情况

| 用户看到的提示 | 含义 | 本手册是否适用 |
| --- | --- | --- |
| 「**无法验证开发者**」/「Apple 无法验证」 | 有效 ad-hoc 签名，只是不受信任 | ✅ **适用** |
| 「**已损坏，无法打开**」 | 签名结构失效（**0.1.6 及更早**） | ❌ **不适用** —— 系统不给放行入口，**只能换新包** |

> **判据只有一条**：提示里出现「已损坏」就不是本流程能解决的，直接让用户换 0.1.11。
> 反过来，「无法验证开发者」**不要**让用户重装、更不要怀疑包坏了。

## 二、客服侧准备（发出前）

### 1. 按架构给对包

| 用户「关于本机」里显示 | 发哪个包 |
| --- | --- |
| 芯片 `Apple M1 / M2 / M3 / M4 …` | `HelloPix-0.1.11-arm64.dmg` |
| 处理器 `Intel` | `HelloPix-0.1.11-x64.dmg` |

引导用户：左上角  → **「关于本机」** → 看「芯片」或「处理器」。

> 给错架构的表现是「**无法打开，因为此应用不支持此 Mac 类型**」，与本手册无关，
> 换对包即可。

### 2. 顺带给出 SHA-256（装不上时能先排除"文件传坏了"）

```
arm64  2949f39475d74615d4362015544e89e7311dbad2ab5bfe9b5752bd27ca81921e
x64    a05d21474e94da7d452af4c8628d9c20728e0580e23ea9bee1cbd233d5c5322e
```

用户核对方式（可选）：终端里 `shasum -a 256 ~/Downloads/HelloPix-0.1.11-*.dmg`

## 三、用户操作流程（详细）

### 第 1 步：下载
点官网（或客服发的链接）下载对应架构的 `.dmg`。

### 第 2 步：拖进「应用程序」★关键★

打开 dmg，把 **`Hello Pix`** 拖到旁边的 **`Applications`** 文件夹。

> ⚠️ **不要在 dmg 里直接双击运行，也不要在「下载」文件夹里运行。**
> 那会被 macOS 当作临时文件（App Translocation），**放行了也不会生效**。
> 必须先「安装」到「应用程序」。

### 第 3 步：替换旧版本 ★最常见的失败点★

若弹出：

> **「已存在同名项目"Hello Pix"，要替换吗？」**

→ 必须点 **「替换」**。

**不替换 = 用户双击的仍是旧版本，怎么放行都没用。**
这是「试了还是打不开」的第一大原因。

> 若替换失败，通常是旧版还在运行：先在 Dock 上右键退出旧版
> （或活动监视器结束 `Hello Pix`），再重做第 2 步。

---

### 第 4 步：双击打开

进入「应用程序」→ 双击 **Hello Pix**。从这里开始**按系统版本分岔**：

---

### 第 5 步-A：macOS 15 (Sequoia) 及更新 —— 现在的主流

> macOS 15 起 Apple **移除了「右键打开」这条旁路**。
> 照旧教程写「右键打开」的用户会**照着做却打不开**，然后认定软件有问题。

| # | 用户看到的 / 要做的 | 精确位置 |
| --- | --- | --- |
| 1 | 弹「**"Hello Pix" 无法打开，因为 Apple 无法验证此 App 是否包含恶意软件。**」→ 点 **「完成」** | **不要**点「移到废纸篓」 |
| 2 | 打开 **「系统设置」** | 苹果菜单 → 系统设置 |
| 3 | 进 **「隐私与安全性」** | 左侧栏 |
| 4 | **向下滚到最底部的「安全性」一节** | ⚠️ 按钮藏在面板最下面，最容易漏 |
| 5 | 看到「**已阻止"Hello Pix"以保护 Mac**」→ 点 **「仍要打开」** | 右侧按钮 |
| 6 | 输入**开机密码**（或 Touch ID） | |
| 7 | 确认框「**确定要打开"Hello Pix"吗？**」→ 点 **「打开」** | |
| 8 | ✅ 应用启动 | |

> ⏱️ **「仍要打开」只在用户刚尝试打开之后约 1 小时内出现。**
> 第 5 步找不到按钮 → 回「应用程序」**重新双击一次**，再进系统设置。

---

### 第 5 步-B：macOS 14 及更早

1. 「应用程序」里 **右键**（或按住 Control 点）**Hello Pix** → 选 **「打开」**
2. 弹窗会多出一个 **「打开」** 按钮（普通双击时只有「移到废纸篓」）→ 点它
3. 可能再问一次「确定要打开？」→ 再点 **「打开」**
4. ✅ 应用启动

---

### 第 6 步：确认成功

- [ ] Hello Pix 窗口正常打开（不是白屏）
- [ ] 「关于」面板显示版本 **0.1.11**
- [ ] **关掉再双击一次，不再弹任何提示** ← 这一步才证明放行生效

## 四、失败对照表（客服速查）

| 用户说 | 真实原因 | 处置 |
| --- | --- | --- |
| 提示「**已损坏，无法打开**」 | 装的是 **0.1.6 及更早**（签名结构失效） | **必须换 0.1.11 新包**；放行操作无效，别让用户重复试 |
| 系统设置里**找不到「仍要打开」** | 超过 1 小时有效窗口 / 从未双击尝试过 | 回「应用程序」**重新双击一次**，再进系统设置 |
| 放行了，**打开还是旧版本** | 第 3 步没有替换旧版 | 删掉「应用程序」里的 Hello Pix，重新拖入并选「替换」 |
| 双击**没反应 / 一闪而过** | 在 dmg 或「下载」里直接运行 | 必须先拖进「应用程序」，再从那里双击 |
| 提示「**不支持此 Mac 类型**」 | 架构给错（arm64 / x64） | 按「关于本机」的芯片重新发包 |
| 一打开就**闪退** | 旧版残留 / 被隐私或杀软工具拦 | 让用户发客户端日志（0.1.6 起有「打开日志目录」），并确认没有旧版残留 |
| 提示「**应用已损坏**」但版本确实是 0.1.11 | 极可能是**下载被截断**（网络中断导致文件不完整） | 让用户核对 SHA-256；不符就**重新下载** |

## 五、快捷方式（可选叠加）

若用户嫌系统设置麻烦，给这条命令 —— **效果等价**，跳过第 5 步-A：

```bash
xattr -cr /Applications/Hello\ Pix.app
```

原理：去掉下载时打上的 `com.apple.quarantine` 隔离标记，而 Gatekeeper 的首次检查正是由它触发。

> 更彻底的变体：用 `curl` 下载**不产生**隔离标记，可做到零提示安装（已在真实环境验证）。
> 需要时再提供，普通用户不必走到这一步。

## 六、客服话术模板（可直接复制）

### 开场（把话说在前面，能砍掉大半来回）

> 您好，macOS 安装包**还没做 Apple 收费公证**，所以装好后**第一次打开会被系统拦一下** —— 这是正常的，不是软件坏了。按我下面的三步放行一次，**以后就是双击直接开**，一分钟就好。

### 首次回复（连发放行步骤）

> **第 1 步**：打开下载的 dmg，把「Hello Pix」**拖进「应用程序」文件夹**。
> 　请**不要**在 dmg 里或「下载」文件夹里直接双击运行，那样放行不会生效。
> 　如果提示「已存在同名项目，要替换吗？」—— **一定点「替换」**（这是最常见的原因）。
>
> **第 2 步**：到「应用程序」里双击 Hello Pix。
> 　· 如果您的系统是 **macOS 15 或更新**：提示框点「完成」→ 打开**系统设置 → 隐私与安全性** → **滚到最底部**的「安全性」一节 → 点「**仍要打开**」→ 输入开机密码 → 再点「打开」。
> 　· 如果您的系统是 **macOS 14 或更早**：在「应用程序」里**右键**点 Hello Pix → **「打开」** → 再点一次「打开」。
>
> **第 3 步**：关掉 Hello Pix 再双击一次，**不再有任何提示**就说明成功了。

### 用户说「系统设置里找不到那个按钮」

> 那个「**仍要打开**」按钮**只在您刚尝试打开之后的一小时内出现**。
> 请先回到「应用程序」**再双击一次** Hello Pix，提示点「完成」，
> 然后**立刻**打开 系统设置 → 隐私与安全性 → **滚到最底部**，就能看到了。

### 用户说「点完还是打不开」→ 先问这一句

> 麻烦确认一下：您在「应用程序」文件夹里看到的 Hello Pix，**是刚替换过的那一个**吗？
> 如果之前装过旧版，没有点「替换」的话，双击的还是旧版本 —— 这样怎么放行都不会生效。

### 用户说「提示已损坏」

> 那个是 **0.1.6 或更早**的版本，它的签名有缺陷，系统**不给放行入口**，所以怎么点都没用。
> 请重新下载最新版：**https://pixfanyi.com**（下载后记得选「替换」）。

## 七、这套引导放在哪三处（已全部就位）

客户在**下载时、安装时、被拦时**三个时点都能看到说明，不必找客服：

| # | 位置 | 内容 |
| --- | --- | --- |
| 1 | `client_releases.note`（官网下载按钮旁） | 「系统安全设置中手动允许」（迁移 037 写入） |
| 2 | 官网下载区折叠块 `.install-help` | `src/components/Landing.vue`，含 Sequoia / 旧版 / 已损坏 三分支 + 「替换」警示 |
| 3 | dmg 内《首次打开说明.txt》 | `desktop/build/首次打开说明.txt`，含「替换旧版」与失败对照 |

> ⚠️ **dmg 内说明的改动只对"下一个构建出来的包"生效。**
> 已发布的 0.1.11 两个 dmg **不会再重新构建**（electron-builder 构建不可复现，
> 重打会产生与验收不一致的字节，且会让线上 SHA 与留档不符）。
> 因此现在下载 0.1.11 的用户拿到的仍是旧版说明 —— 但官网（第 2 处）**已经**写了
> 「替换」警示，配合本话术足够覆盖。

## 八、什么时候可以删掉这套引导

拿到 Apple Developer 证书、完成 **Developer ID 签名 + 公证**之后：

```bash
cd desktop && npm run pack:mac:release    # 带 PIX_REQUIRE_NOTARIZED=1
```

验收通过（新建用户账号上 `spctl -a -vvv` 出现 `source=Notarized Developer ID`）后，
以上三处引导**都可以删掉**，用户双击即开、零提示。
代码侧早已铺好（`identity` 未写死、`hardenedRuntime`/`notarize` 已开、
`after-pack.js` / `after-sign.js` 两个 fail-closed 守卫已注册），无需再改。
