# P0/P1 安全审查基线

## 结论

Request Changes。现有会话、CSRF、设备绑定和基础限流有效，但仍存在发布阻断项。

## 严重问题

- 生产服务直接加载内存 Mock、公开种子口令且数据重启丢失。
- Electron 远程 WebContentsView 缺少导航边界，并向页面暴露带登录态的翻译 IPC。
- API 线路、自定义网页和更新地址缺少统一主进程校验，存在 SSRF 与供应链风险。
- 工单编辑使用 mass assignment，可覆盖资源归属字段。
- 翻译缓存跨租户共享且命中不计费；异步外调前未预扣，存在并发双花。
- Element UI HTML 弹窗拼接业务数据，存在存储型 XSS 面。

## 高优先级问题

- Guest 权限默认全部允许。
- 登录、代理密码和聊天译文存在明文暴露或落盘风险。
- 分享密码、分页、内存 grant/cache 与 operator 权限需要收紧。
- 软件更新尚无包签名与完整性校验，不能启用自动安装。

## 验收

- 新增对应负向测试，修复前可复现、修复后稳定通过。
- `npm run test:security`、生产构建和 Electron 冒烟全部通过。
- 真实数据库、支付验签和安装包签名完成前保持上线阻断。

# PostgreSQL + Redis 核心迁移复审

## 结论

Approved（限正式核心数据底座）。认证、用户/子账号、工单、字符余额、翻译账本、
管理员和站点核心接口已切换到 PostgreSQL + Redis；生产进程不再加载内存 Mock。
支付、真实翻译厂商、注册找回、导出与安装包签名仍未完成，收费上线继续受阻。

## 复审中发现并关闭的问题

### 🔴 ioredis 调用协议不兼容

- 位置：`server/stores/redis-client.js`
- 复现：真实 Client 登录创建 session 时 Redis 返回
  `ERR value is not an integer or out of range`。
- 原因：测试桩接受 node-redis 的 options-object 调用，但 ioredis 的 `SET`/`EVAL`
  使用位置参数。
- 修复：显式识别 ioredis 并选择位置参数，同时保留 node-redis/test-double 兼容。
- 验证：真实 Redis session 创建、读取和按主体撤销均通过。

### 🔴 reservation 结算 SQL 参数类型冲突

- 位置：`server/services/core-service.js`
- 复现：翻译完成结算时 PostgreSQL 返回
  `inconsistent types deduced for parameter $2`。
- 修复：提交与释放使用各自固定状态 SQL，仅业务值使用参数，保持幂等锁定。
- 验证：成功结算、失败退款、同文退款和超时恢复通过真实数据库测试。

### 🔴 未接线通道可能使用演示结果收费

- 位置：`server/services/core-service.js`
- 风险：`wired=false` 的通道仍可能返回本地演示词典结果并扣字符。
- 修复：在 reservation 和扣费前强制检查 `wired`；正式 provider 默认 fail-closed，
  并移除正式服务对 Mock 翻译模块的依赖。
- 验证：未接线通道返回 `503 / ENGINE_NOT_CONFIGURED`，余额和 reservation 均不变。

### 🟡 正式临时安全状态未完全接线

- 位置：`server/routes/production.js`、`server/lib/captcha.js`
- 修复：登录、验证码、分享口令和翻译增加 Redis 双维限流；验证码改为只保存摘要；
  登录失败写 `login_logs`。

### 🟡 管理员可绕过余额账本

- 位置：`server/routes/production.js`
- 修复：用户编辑接口拒绝直接设置余额，只允许使用事务化字符调整接口；支付结算状态
  在真实回调验签完成前改为 `503 / NOT_MIGRATED`。
