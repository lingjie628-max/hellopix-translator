# 桌面端设计规范（借鉴自竞品 HelloWorld Mac 2.0.0）

> 来源：竞品 Mac 桌面端源码分析（Electron + ExtJS 5.1.1 + SASS 主题）
> 说明：本文件只记录**设计数值与布局决策**，是行业通用的度量信息，不含其任何源代码。
> 我们的实现用自己的代码写，结构照我们的技术栈（原生 CSS + flex/grid）。

---

## 一、窗口参数

| 项 | 竞品 | 说明 |
|---|---|---|
| 默认尺寸 | **源码不可读**（主进程是 bytenode 字节码 `main.jsc`） | 仅能确认构造时显式传了 width/height |
| 最小/最大尺寸 | **未设置**（字符串表无 minWidth/minHeight） | 推断为不限制 |
| **记忆上次尺寸** | **有**：`scheduleSaveWindowBounds` + 防抖定时器 | 这是我们的差距项 |
| 位置校正 | 按所有显示器的 `workArea` 校正，防止窗口跑到屏幕外 | 多显示器场景 |
| DPI / zoom 适配 | 主进程无；仅内嵌网页可 ±0.25 缩放 | 不做界面等比缩放 |

**我们要做的**：加入窗口 bounds 持久化（关闭时存、启动时恢复，并校验仍落在可见区域内）。

## 二、翻译设置工具栏（核心）

### 布局机制

竞品用 ExtJS `checkboxgroup` + `columns: 4`，渲染为表格，**列优先填充**：

```
列0: 发送翻译   列1: 你的语种   列2: 翻译语种   列3: 翻译中文
列0: 消息翻译   列1: 消息语种   列2: 翻译语种   列3: 群组翻译
列0: 翻译平台   列1: 字体大小   列2: 字体颜色
```

渲染出来正好是**三行 × 四列**（与截图完全吻合）。

### 关键数值

| 项 | 竞品值 | 我们当前 | 处理 |
|---|---|---|---|
| 列宽 | **25%（比例分配）** | 无固定列宽，靠 flex 换行 | 改为 `grid-template-columns: repeat(4, minmax(0,1fr))` |
| 控件宽 | **固定 215px** | `min-width:84px; max-width:140px` | 改为固定 215px |
| 标签宽 | **固定 70px**（中文）/ 150px（英文） | 无固定值 | 中文固定 70px |
| 单元格左边距 | **70px**（`margin: 5px 0 5px 70px`） | 无 | — |
| 单格最小总宽 | **285px**（70 + 215） | ~84 + 标签 | — |
| **设计最小窗口宽** | **≈1150px**（4×285 + 内边距 + 边框） | `minWidth: 1100` | **提到 1160** |
| 工具栏总高 | **≈128px**（标题栏 24 + 3 行 × 34 + 2） | `max-height: 96px` | 按需调整 |
| 行高 | **34px**（控件 24 + 上下 margin 5+5） | 24 + gap 8 | 行距压到 5px |
| 工具栏内边距 | `0 4px` | `8px 12px` | 参考 |
| 是否有标题栏 | **有**，24px 可折叠「全局翻译设置」 | 无 | 可选 |

### 主题数值（编译后的 main.css 中提取）

| 元素 | 数值 |
|---|---|
| **标签** | `14px / 17px`，字重 **500**，颜色 **#666**，min-height 24px，padding-top 4px、padding-right 5px |
| **控件文字** | `13px / 15px`，字重 **300**，min-height 22px，padding `4px 6px 3px 6px` |
| **控件高度** | **24px** ← 我们已一致 ✅ |
| **下拉箭头宽** | **22px** |
| 面板标题 | 15px / 16px，字重 300，颜色 #2e658e，padding 3px |
| 面板正文 | 13px，字重 300 |

**我们要调的**：标签从 12px 提到 **13–14px**；行距从 8px 压到 **5px**。

## 三、整体缩放

**竞品不存在全局缩放机制**：`rem` 出现 0 次、无 `html{font-size}`、无 CSS 变量、全部 px 硬编码。

→ 我们**同样不做等比缩放**，直接写像素值即可，与竞品一致。

## 四、复刻方案（推荐实现路径）

竞品那套"列宽 25% + 控件固定 215px + 标签 70px"的组合，等价于：

```css
/* 四列网格，列宽按比例分配 */
.trans-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 5px 0;                 /* 行距 5px（竞品行高 34 = 24 控件 + 5 + 5） */
  padding: 0 4px;
}
/* 单元格：标签固定 70px，控件固定 215px，整体左边距 70px 与竞品一致 */
.trans-cell {
  display: flex;
  align-items: center;
  gap: 0;
  padding-left: 70px;         /* 等价于竞品的 margin-left:70px */
}
.trans-cell > .cell-label {
  width: 70px;
  flex: 0 0 70px;
  font-size: 14px;            /* 竞品 14px/17px */
  line-height: 17px;
  font-weight: 500;
  color: #666;
}
.trans-cell > select {
  width: 215px;               /* 竞品固定 215px */
  height: 24px;               /* 已一致 */
  font-size: 13px;
  line-height: 15px;
}
```

**最小窗口宽**：`4 × 285 + 12 ≈ 1152` → `minWidth: 1160`。

## 五、实施顺序（每步独立验证 + 可回滚）

1. **窗口**：加 bounds 持久化 + minWidth 提到 1160
2. **设计变量**：把上面的字号/间距/尺寸抽成 CSS 变量（竞品没有，但对我们有利）
3. **工具栏网格化**：`.trans-grid` + `.trans-cell`，四处标签改到控件上方/左侧按规范
4. **其余区域**：顶部导航、工作区、底部栏按同一套梯度过一遍
5. **优化**：188 语言搜索、多开网格等我们独有的部分，在规范基础上适配

## 六、注意事项

- 竞品用 **ExtJS 组件树**，我们用**原生 CSS + flex/grid** —— 只对齐**视觉结果与数值**，不照搬其技术实现
- 主进程尺寸值是其字节码，**无法读取**，所以窗口默认尺寸我们按自己的屏幕自适应策略来（已验证可用）
- 竞品**没有**：窗口缩放体系、设计变量文件、响应式断点。这三样如果不做，是合理的一致选择
