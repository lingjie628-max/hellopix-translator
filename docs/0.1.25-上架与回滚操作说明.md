## 3. 本版内容（相对 0.1.24）

### 3.1 群聊自动翻译：一半翻译、一半没翻译（观感缺陷，用户报障）

**现象**：开启「群聊自动翻译」后，打开群聊仍出现需要手点的「译」按钮，
且会话里**一部分消息被翻译、另一部分没有**。

**根因**：`MessageParser.messageAction` 里有一条
`if (s.group && s.historic) return 'chip'` —— 它把「群聊=自动」降级成**半自动**：
只有会话进行中新到的消息自动翻，打开会话时**已经在页面上**的那批只挂「译」按钮。

**修法（四条）**：

1. 删除「群聊=自动、历史只给按钮」的闸门（连同 `createHistoryGate` / `isHistoric` /
   状态里的 `historic` 一并删干净）。用户裁定：群聊=自动就该把会话里出现的**全部**消息
   自动翻，且**不再出现任何「译」**。
2. 自动翻译改**有界并发、新的先翻**（`AUTO_POOL_SIZE = 3`，倒序入队）。旧的串行扫描
   翻几十条要等半分钟 —— 这正是"翻一半"的观感来源；上限不能去掉（翻译与**发送**共用连接池）。
3. 切到自动时收掉手动留下的残留「译」（`removeStaleChip`，`busy` 态不动）。
4. `paint` 加「内容没变就不写 DOM」（`if (box && box.textContent === translated) return true`），
   掐断 MutationObserver 自激循环（0.1.24 真机单条消息渲染 trace 一秒 33 次）。

**为什么不重复扣费**（删掉历史闸门的前提）：同一条消息翻多少次都只计一次费，三层保证 ——
客户端 `transRequestId` 恒定（`desktop:${deviceId}:${fingerprint}:${generation}`）、
服务端 `core.translate` 按 `idempotency_key` 查预留命中即返回、
客户端 `transCache` + 服务端 `translationCache` 挡重复调用。
**成本上限 = "从没翻过的正文"，不是"翻了多少次"。** 已被单测锁死。

**保留的唯一计费护栏**：群聊 + 「群聊自动翻译」= 手动 → 一条都不自动翻，只给「译」按钮。
真机验收点：该模式下 `trigger=auto_receive` 必须为 0。

### 3.2 新增取证埋点

`AUTO_DISPATCH`（`candidates` / `dispatched` / `queued` / `running` / `chipRemoved`），
配 `0.1.25-交付包/rc025-collect.sh` 采集。

## 6. 回滚

```sql
UPDATE client_releases SET enabled = false, updated_at = NOW() WHERE version = '0.1.25';
UPDATE client_releases SET enabled = true,  updated_at = NOW() WHERE version = '0.1.15';
```

回滚只是让**更新提示**回到 0.1.15，**不会**把已经装成 0.1.25 的用户变回去。
真要让用户退回，得再发一个版本号更大的包（客户端只认更大的版本号）。

> ⚠️ 本次回滚的代价：0.1.15 是停售前的最后一版，且 `/opt/hello-pix/downloads/` 里
> 它的文件仍在（保留以便回滚）。若回滚原因是 0.1.25 引入了新问题，
> 应**优先热修复并升到 0.1.26**，而不是回退到 0.1.15。

**没有迁移需要回滚**（本版是纯客户端修复）。
