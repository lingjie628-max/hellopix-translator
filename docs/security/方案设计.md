# Hello Pix HTTPS 与接口安全方案

采用单台 Linux 云服务器、Nginx TLS 终止和本机 Node 服务。Nginx 负责 HTTPS、HSTS、静态资源与边缘限流；Node 负责随机服务端会话、HttpOnly Cookie、CSRF、密码哈希、角色权限、设备绑定和账号级限流。

关键安全规则：

- 未登录请求不得回落到演示商户，未声明接口默认要求有效会话。
- 商户、桌面客户端和管理员使用不可预测的独立会话，管理员角色在服务端验证。
- 所有状态修改请求校验 CSRF；登录、验证码、翻译和导出使用独立限流。
- Node 只监听 `127.0.0.1:3000`，公网仅开放 Nginx 的 80/443。
- 正式支付验签、真实数据库和 Redis 不属于当前 Mock 安全骨架，收费上线前必须完成。

实现文件：

- `server/security.js`：密码、会话、CSRF、安全响应头、限流。
- `server/index.js`：生产服务入口。
- `deploy/nginx/hello-pix.conf`：HTTPS 与边缘限流。
- `deploy/hello-pix.service`：systemd 服务。
- `test/security.test.js`：认证和越权回归测试。
