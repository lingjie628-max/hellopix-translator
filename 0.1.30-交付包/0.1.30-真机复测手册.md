# Hello Pix 0.1.30 真机复测手册

> **本版的重点是「开满不闪退」。** 请在**报障那台机器**上走完第 1～3 步。

---

## 0. 装之前先记一笔（很重要）

先在**出问题的那台机器**上打开**旧版** Hello Pix，反复开 / 关实例十几轮，
然后主界面 → 设置 → 「客户端日志」导出（或跑 `rc030-collect.sh`）。

> 为什么要这样：旧版在这个场景下会**闪退**，而闪退往往来不及写日志。
> 先把日志捞出来，能帮我们确认"崩之前最后发生了什么"。
>
> 另外记一下：**旧版你能开到第几个才崩？**（用户报的是 18 个左右）
> 这个数字对判断很有用 —— 它是你机器上句柄上限的直接体现。

---

## 1. 【核心】开到上限必须**提示**，不许闪退

**步骤**：
1. 新建一个账号 / 用一个账号。
2. 反复点「+」开新实例（同一个平台或不同平台都行），一直开到 **20 个**。
3. 在已有 20 个的情况下，**再点一次「+」**。

**期望结果**：

| 观察点 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 表现 | 弹出**系统提示框**「无法再开新窗口」 | **应用闪退** |
| 提示内容 | 写明「最多同时开 20 个」+「请关掉几个不用的」 | 什么都不提示 |
| 应用状态 | **照常可用** —— 已开的 20 个窗口继续正常收发翻译 | 进程消失 |
| 日志 | `resource` 分类有一行 warn，记下原因与当前句柄数 | 无记录 |

> 关键区别：**崩溃时用户什么都看不到；拒绝时用户知道该怎么做。**

---

## 2. 【核心】关掉几个之后必须能继续开

**步骤**：
1. 承接上一步（当前 20 个，已弹过一次提示）。
2. 关掉 **3 个**不用的实例（当前 17 个）。
3. 再点「+」。

**期望结果**：

| 观察点 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 能否开出新实例 | **能**，正常加载 | 仍然被拒 |
| 新实例能否翻译 | 能 | 不能 |

> 这条验证"上限是**动态**的，不是一次性锁死"。

---

## 3. 【核心】反复开关不再加速触顶

**背景**：旧版每次"开→关"会**永久泄漏约 8 个句柄**，
所以有的人"开到 12 个就不行了"。本版收尾做了加固。

**步骤**：
1. 连续做 **10 轮**「开一个新实例 → 用几秒 → 关掉它」。
2. 然后一口气开到 **19 个**。

**期望结果**：

| 观察点 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 能否开满 19 个 | 能 | 中途就崩 / 就拒 |
| 什么时候才提示 | 到 20 个才提示 | 十几轮之后就开始莫名拒绝 |

> 若这一步提前触顶，请把日志发回 —— 说明还有别的句柄消耗路径没找到。

## 5. 收集日志发回

在**出问题的那台机器**上跑：

```bash
# Windows 用 Git Bash / WSL
bash rc030-collect.sh
```

或手动：主界面 → 设置 → 客户端日志 → 导出。连同以下信息一起发：

1. Windows / macOS 版本（Windows 跑 `winver`）
2. **旧版能开到第几个才崩**（第 0 步记下的数字）
3. 新版开到第几个开始提示
4. 复测时**卡在第几步**、屏幕上是什么
5. 特别要「**崩/提示那一瞬间**」附近的日志时间段

| 验收 | 结果 |
|---|---|
| `node --test test/tab-budget.test.js` | **18 / 18 通过** |
| `electron scripts/verify-tab-budget-electron.js` | **9 / 9 通过** |
| 全量 `node --test test/*.test.js` | **1165 项 / 1151 通过 / 0 失败** |

真 Electron 实测的关键记录：

| 断言 | 实测值 |
|---|---|
| 每个实例消耗的句柄数 | **19.2 个**（预算按 26 算） |
| 20 个实例累计句柄 | 39 → **520** |
| 连续 30 次"拒绝"判断消耗的句柄 | **0**（87 → 87） |
| 拒绝之后能否正常建窗口 | **能** |
| 反复开关 30 次的永久泄漏 | 242 个句柄（≈8.1/次，Electron 33 原生行为） |

> 最后一条说明了为什么必须有**显式的窗口数上限**：
> 光看句柄水位会因历史泄漏而误判，而数字上限是确定的、可解释的。
