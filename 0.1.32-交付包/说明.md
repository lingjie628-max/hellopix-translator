# Hello Pix 0.1.32 交付说明

> **一句话**：两个修复,都由**真机日志取证**驱动 —— 一个治「翻译桥未启动」的误报,
> 一个治「窗口黑屏」时什么都不说。

---

## 一、这版修了什么

### ① 翻译桥「未启动」误报

**真机证据**（用户装了 0.1.26、同时开着 **54 个**实例）:

```
  实例            报「未启动」      实际就绪        延迟
  green-39        20:02:54        20:26:47       1433s
  green-48        20:22:28        20:25:26        178s
  green-47        20:22:16        20:24:29        133s
  green-25        19:30:00        19:32:01        120s
  ...
  43 个实例报过「未启动」，其中 42 个后来都就绪了
  中位延迟 28 秒，超 8 秒的 35 个
```

**结论：桥没坏，只是慢。** 54 个渲染进程同时装载把 CPU/磁盘瓜分掉,
preload 跑完 exec + 首次 IPC 远超原来那个 8 秒死线。

**为什么这个误报很伤**：告警文案说「你按回车后消息可能未经翻译直接发出」——
用户看到就不敢用了;侧边栏还会挂一个 ⚠。42 个实例白挂警告,信任就没了。

**修法**:单一死线拆成两段

| | 时长 | 行为 |
|---|---|---|
| 软线 | 8 秒 | 只记 debug,**不判死、不告警** |
| 硬线 | 90 秒 | 仍无消息才判「真未启动」 |

> 装载期就抛错（`__pixPreloadError`）仍是**立即判死** —— 那是确凿证据,不必等。

### ② 加载失败「黑屏」

**真机证据**（同一份日志）:

```
  19:27:48  /client/session  连不上服务器（UND_ERR_CONNECT_TIMEOUT）
            attempted addresses: 104.21.6.157:443, timeout: 4000ms
  20:26:13  同样超时（这次是 172.67.134.254:443）
  18:20~20:26 共 8 次 NETWORK_TIMEOUT / NETWORK_UNREACHABLE
```

那两个 IP 都属于 **Cloudflare** —— **这台机器连我们自己的后端都连不上**。

用户表现:「**有的窗口直接就是黑的,有的可以打开扫码**」——
同一个软件、同一版本、同一时刻,差别只在"那一刻这个实例连没连上"。

**缺陷在哪**:`startTabLoad()` 里原本只有一句

```javascript
tab.view.webContents.loadURL(tab.url)   // 没有 catch，没有 did-fail-load
```

失败后 Chromium **什么都不画**,用户看到的就是 `createWebView` 设的背景色
`#081628` —— 一块看起来像"软件坏了"的深色空白。
**于是「网络不通」被表现成「软件故障」。**

**修法**:新增 `desktop/load-error-page.js`,失败时显示一个能自己重试的错误页:

```
!  接粉顾问5
   连接超时
   网络太慢或对方无响应。请检查网络，或换一个更快的代理线路后重试。
   [ 重新加载 ]
   错误码 -118 · ERR_CONNECTION_TIMED_OUT
```

三个关键设计:

- **`data:` URL** —— 离线可渲染（网络正好是坏的,错误页自己再加载不出来就没意义）
- **重试走 `location.href`,不走 IPC** —— 主进程卡住时按钮仍能用
  （而这个用户恰好也遇到卡顿,走 IPC 的按钮会点不动）
- **覆盖常见错误码**,每条都回答「是什么问题 + 该做什么」;
  SOCKS5 失败会**直接指向「代理设置」**

## 二、顺带修掉的两个隐患

1. **`load-error-page.js` 漏在打包白名单外** —— 与 `tab-budget.js` 当初同一个坑,
   漏了就是 `MODULE_NOT_FOUND`,**安装包启动即崩**。已补,
   并新增一条**通用护栏测试**:自动核对 `main.js` 所有 `require('./x')`
   都在 `build.files` 里,防止以后再犯。

2. 一个旧测试用 `slice(0, 400)` 死板取样,被新加代码挤出窗口而脆断 ——
   是**测试写脆了**,不是功能坏了。已改为按函数体取样。

## 四、真机复测

### 1. 【核心】窗口不再"黑屏不说原因"

1. 故意把某个实例的代理改成一个**坏节点**（或拔网线）。
2. 打开那个实例。

| 观察点 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 表现 | 显示错误页,有标题 + 建议 + **重新加载**按钮 | 一片深色空白,什么都不说 |
| 标题 | 「连接超时」「代理连不上」这类具体原因 | 只说"打不开" |
| 按钮 | 点击后真的重新加载 | 点了没反应 |
| 日志 | `load` 一行 warn,含错误码 | 无记录 |

### 2. 【核心】「翻译桥未启动」不再误报

1. 一次开 **20 个以上**实例。
2. 观察侧边栏是否还出现 ⚠。

| 观察点 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| 20+ 实例时 | **不再**大面积出现 ⚠ | 一大片 ⚠（那是旧版） |
| 日志 | 有 `debug` 级"...继续观察" | 满屏 ERROR「未启动」 |
| 真的坏掉时 | 90 秒后仍会告警 | 完全不再告警（漏报） |

> 注意第 3 条:这版是**降低误报**,不是**取消告警**。真坏的实例仍会报出来。

### 3. 窗口上限仍是内存水位（0.1.31 的能力）

内存接近 90% 时点「+」→ 弹「运行内存不足」;关掉一些后能继续开。

### 4. 回归项

| 项 | 期望 |
|---|---|
| 发送 / 接收翻译 | 正常 |
| 译文可复制（0.1.27） | 能复制 |
| 节点检测（0.1.29/31） | 坏节点 8 秒内给**可读**原因,不再显示 `reply=8` |
| 图文一起发（0.1.28） | 文字也翻译 |

## 五、重要:这版**没有**解决用户的黑屏根因

**软件现在会清楚地说"连不上、请检查网络或代理",但如果用户的网络/代理确实不通,
他还是开不了。**

日志显示那台机器连 `pixfanyi.com`（Cloudflare）都连不上 —— 这是**网络侧**问题。
建议向用户确认:

1. 是不是开了代理/VPN?那个节点还活着吗?
2. 换网络（例如手机热点）还能不能开?
3. 是**所有**窗口都黑,还是只有部分?
4. 是否同时开着 50+ 实例（会抢带宽,加剧问题）?
